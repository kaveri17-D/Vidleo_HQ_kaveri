## 2. Technical Architecture: How YouTube Media Bytes Are Acquired

### 2.1 The YouTube Delivery Reality (SABR & UMP)
Modern YouTube watch pages stream media using YouTube's proprietary SABR (Server-Side Adaptive Bitrate) architecture over UMP (**YouTube Media Protocol** / `application/vnd.yt-ump`). 
Direct HTTP GET requests to `googlevideo.com/videoplayback?itag=...` fail with HTTP 403 Forbidden due to session binding and cipher constraints. However, within the user's active Chrome browser session, the browser holds the authenticated playback session.

### 2.2 Acquisition Mechanism (Chrome DevTools Protocol)
Rather than scraping or attempting token forgery, Vidleo attaches to the active playback session via the Chrome DevTools Protocol (`chrome.debugger` API, `Network` domain):
1. Extension attaches `chrome.debugger.attach({ tabId }, "1.3")`.
2. Enables network monitoring with extended buffer sizes: `Network.enable` (`maxResourceBufferSize: 100MB`).
3. Observes `Network.loadingFinished` on player network requests.
4. Directly extracts the genuine response body: `Network.getResponseBody({ requestId })`.

### 2.3 UMP Demuxing Architecture
YouTube's UMP stream multiplexes multiple parts:
- `Part Type 20` (`MEDIA_HEADER`): Protobuf message containing metadata:
  - Sequence number (`sequenceNumber`)
  - Target format / itag (`itag`: 251 for Opus audio, 395 for AV1 video)
  - Initialization segment flag (`isInitSeg`)
  - Start time and duration in milliseconds
  - Content length
- `Part Type 21` (`MEDIA`): Media data payload prefixed by a single-byte subsegment stream ID.
- `Part Type 22` (`MEDIA_END`): Finalizes subsegment processing.

By demuxing the UMP parts using `UmpReader`:
1. **Audio Track (itag 251)**: Parts 0, 2, and 5 are concatenated into a valid, standard WebM container (`matroska,webm`) containing the 19.021s Opus stereo audio stream produced by `google/video-file`.
2. **Video Track (itag 395)**: Part 1 (`ftyp` + `moov` initialization boxes) is prepended to media fragments 3, 4, and 6 (`moof` + `mdat`), creating a 284-frame AV1 fragmented MP4 stream (18.933s).
3. **Local Remuxing**: The pure client-acquired video stream is stream-copied (`-c:v copy`) and muxed with the audio stream (`-c:a aac`) via FFmpeg, with `-movflags +faststart` placing the index at the beginning for instantaneous playback.
